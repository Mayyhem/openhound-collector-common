# Reference assertions and optional console formatting

The SQL completion initiative needs exact comparisons to a pinned Go collector.
Existing SCCM tests match node properties, while the reference also tests edge
IDs when its output omits native AD nodes. Filtering properties before checking
counts could hide an incorrect second edge. The Go console format also differs
from the framework's existing format.

## Shared changes

`integration_testing/cases.py` adds optional endpoint-ID patterns, name-before-@
matching, checking properties on every matching edge, and exact property values.
Existing defaults stay unchanged. `matcher.py` handles only `*` and `?` as ID
wildcards, preserving literal brackets. Exact property matching preserves value
types, letter case, and list order. `runner.py` checks every matching edge when
requested instead of letting property filtering hide a bad record. Count limits
continue to use the existing `CountSpec`; callers explicitly choose any allowed
extra counts. SQL cases and permission interpretations remain in the SQL repo.

`logging/console.py` adds an optional `GoConsoleFormatter`. It renders UTC whole
seconds, five log levels, one target label, and ordered detail fields. Colors use
the pinned reference's FNV-1a target hash and palette. `console_supports_color`
keeps redirected output plain and uses Windows console-mode APIs for terminals.
`log_event` uses the ordinary shared logger. Known secret values, sensitive field
names, and inline passwords can be redacted. A caller must select this formatter
and supply its known secrets; importing it installs no handlers or policy.

`LogContextFilter` preserves the original message and context in private record
attributes before adding its established text prefix. Existing formatters ignore
those private fields. The new formatter can therefore avoid duplicated target
labels without changing SCCM's prefixed messages or adding new file-log fields.

No dependency is added. No collector is imported by this library. A separate
assertion engine and global formatter replacement were rejected because they
would duplicate existing tests or change other extensions' output.

## Reference and checks

Fixed transcripts in `tests/fixtures/go_console.json` were generated by the
unchanged logging handler from SpecterOps/MSSQLHound 2.0.4 at commit
`92efaeb892cd3e43dbdd5b4308dbf55383db1453`, in a disposable source copy. The export
test itself lives with the SQL collector's developer reference tools. These
Apache-2.0-derived fixtures retain the source file/commit/license metadata; this
repository's `LICENSE` provides the license terms. Go is not a runtime dependency.

Windows behavior was checked against
[Microsoft's console-mode documentation](https://learn.microsoft.com/en-us/windows/console/setconsolemode).
Value rendering follows the pinned handler and
[Go's slog values](https://pkg.go.dev/log/slog#Value.String).

Initial focused assertion checks: 29 passed. Initial console/context checks:
27 passed, including exact plain/color transcripts, context, concurrent target
ordering, redaction, and unchanged default messages. Expanded shared suite:
172 passed, one Python-version skip; lint and mypy passed. Later private-attribute
and exact-value refinements require the focused recheck recorded in the SQL
initiative status before this work is called complete.
